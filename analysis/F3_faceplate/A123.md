## A1 Property values of the faceplate objects

**Content of the type.** The screen items in `ILFaceplateTypeData` are ordinary `ILScreenItemData`. Their values are in the same expando as for screen items (`IPropertyExpandoAttributes` per H-020, previously called `IPropertyDynamicExpandoAttributes`) and can be read unchanged with `Hmi.screen_properties()`. Examples from FP_Basic (1004:00cd:206d):

| Object | Original on FP_Basic (F01) | Copy in faceplate FP_Basic |
| --- | --- | --- |
| B_Rect1 | Left 20, Top 20, 120×60, BackColor 0xFFFF0000 | Left 10, Top 10, 120×60, BackColor 0xFFFF0000 |
| B_Ellipse1 | CenterX 80, CenterY 150, RadiusX 60, RadiusY 30 | CenterX 70, CenterY 140, same radii |
| B_Polygon1 | 4 points, last (100,55) | same points, Left 430 instead of 440 |

"Create faceplate" shifts all objects by (−10, −10): the frame around the selection gets a 10-pixel margin. Properties and points otherwise stay the same.

**Faceplate content itself** (`ILFaceplateTypeData`, both types built the same way):

**Layer finding (re MCP-059).** In the crash copy, 63 of 64 screen items and containers have the key `08`, and all 63 resolve to the layer GUID. Only X_Rect1 (created via TiaMcpXE `importXml`) has neither `08` nor a reference entry. This confirms the cause of the editor crash at file level. For `docs\spec\unified-properties.md` (Unified thread): `08` = Layer (reference), `1f` = CaptionColor, `7508` = StyleItemClass.

## A2 CoreMapArray (IFaceplateInterface)

- `IFaceplateInterface` (InterfaceEvents, InterfaceProperties, TagInterfaceProperties, each `CoreMapArray`, metamodel type `Array`) sits on `ILFaceplateTypeData` in slot 9. In both faceplates of the crash copy **no block** is present (slot offset 0): an empty interface is not stored at all, not even as an empty array.
- Expected format per H-L2-1 (L2 report, commit 4e43505): u32 overall length, u32 count, count × u32 offset relative to the start of the value, then the elements; the elements are structures like a set block. The content of `CoreMap` cannot be checked without an example; only with F11 (one interface tag), F16 (interface properties) and F18 (interface event).

## A3 Version, state, default, author

| Field | FP_Basic (version 0003:00d3:2019) | FP_Controls (version 0003:00d3:207f) |
| --- | --- | --- |
| `IVersionInfo.Version` | `14000000 01000000 00000000 00000000 ffffffff` | same |
| Decoded | u32 length 20, Build 1, Major 0, Minor 0, Revision −1 → **0.0.1** | 0.0.1 |
| `ICoreLibObjectAttributes.State` | Committed | InWork |
| `IVersionInfo.FinalizationTime` | 2026-10-20T17:49:59.722470Z (time of release) | 0001-01-01T00:00:00Z (not released) |
| Default version | `TypeToDefaultVersion` (type → version) and `DefaultVersionToType` present | no default relation |
| Author | `ICoreAttributes.Author` factorybyte, `LastModifiedBy` factorybyte | same |
| Comment | empty (CoreText without cultures) | empty |
| Device version | `MinimumTargetDeviceVersion` 21.0.1.0 (version), '' (type) | same |
| `RelatedPackage` | `SW.HMI.FaceplateVersion_21.0.1.0{21.0.1.0.0}` | same |
| `ICoreAttributes.Version` | '' | '' |

The encoding of the version number is the same as for PLC types (L1 report: 4 × i32 Build, Major, Minor, Revision; L2/H-L2-1: the "3-byte prefix" is the rest of the u32 length 20). The mapping 0.0.1 matches the TIA command log ("V 0.0.1"). A version with Major/Minor ≠ 0 does not exist for faceplates yet (F21/F29 will clarify that).
