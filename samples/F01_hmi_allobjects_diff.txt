== Findings (reported only, no spec)
- All 47 screen items (except the faceplate container) are ILScreenItemData (DL.ModernUI); the Openness type is in ICoreAttributes.Subtype (e.g. HmiRectangle, HmiAlarmControl). The faceplate container has its own type ILFaceplateContainerData (DL.FaceplateLib).
- Screens: ILScreenData, 7 of them (6 FP_*/Main + FP_Flash).
- Property values (position, colors, texts) are in IPropertyDynamicExpandoAttributes; the parser reports a decoding problem there throughout.
- Dynamizations (tag: direct/SingleBit/Range, ProcessValue, Flashing) create NO objects of their own (Dynamics/DL.Dynamics stay 0); they are contained in the expando data of the screen item (I_Rect1: 3218 bytes vs. B_Rect1 534 bytes, plus IEventExpandoAttributes).
- Scripts: 6 HmiScriptEmbeddedData = exactly the 6 created scripts (I_Text1 ForeColor dynamization, FP_Interface BackColor dynamization, S_Button1 Tapped and Down, S_IOField1 ProcessValue Change, FP_Script Loaded); 2 HmiScriptModuleContainerData (one per screen with scripts: FP_Interface, FP_Script).
- Events appear as IAdditionalAttributes keys with the event name (S_Button1: Tapped, Down; FP_Script: Loaded).
- The property event S_IOField1 ProcessValue/Change does not appear in IAdditionalAttributes; S_IOField1 is the only object with a problem in ISoftlinkAttributes.
- Tag dynamizations (I_Rect1, I_Bar1, X_Rect1) go along with problems in IEventExpandoAttributes; the plain ProcessValue binding on the I/O field (I_IOField1) does not.
- Largest object: C_AlarmControl1 (35591 bytes, default columns/views of the alarm control).
- Tombstones in the folder 16 -> 19 (among others the deleted S_Switch1); none in the .zap21.
