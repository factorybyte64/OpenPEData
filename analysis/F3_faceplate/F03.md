## Finding: unresolved tags as shells

FP_Interface and FP_Script were created from screens whose objects were bound to the project tag `HmiTag_Ext1`. In the faceplate, this produces one **HmiTagData "HmiTag_Ext1" without content** each (1008:00e5:24e0 in FP_Interface, 1008:00e5:2544 in FP_Script):

- Only `ICoreAttributes` (Name, IsShell false), no data type, address or tag attributes.
- Link `TRefParent` → "Default tag table" of the hidden faceplate device; the table points back via `TextualReferences` (not via `Content` as for real tags).
- Incoming `ExpandoReferences` from I_Rect1, I_Text1, I_Bar1 and the script ForeColorTrigger.

This matches the docs ("Creating a faceplate type from a screen": the tag reference resolves as soon as a tag of the same name is created in the tag interface). It is very likely the reason why FP_Interface and FP_Script do not compile or cannot be released (user: "some not compilable"). For FP_Controls, the typeless container C_Faceplate1 remains the likely cause (`Error_NonExistingFaceplateType`, see CRASH.md).

**For the user:** in FP_Interface and FP_Script, create a tag `HmiTag_Ext1` (Bool) under "Tag interface"; then they should be releasable. That would also be a good sample for the first interface tag (F11).
