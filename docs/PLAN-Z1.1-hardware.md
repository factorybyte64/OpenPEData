# Plan Z1.1: Fully understand devices and networks

Goals and non-goals: see [GOALS.md](GOALS.md) (the only valid source). This plan implements Z1.1; the CPU properties from Z1.2 go along via the same mechanism. As of 2026-10-25.

## Starting point (finding 2026-10-24, see docs\spec\hw-config.md)

- The hardware is stored as normal records in the plf: `DeviceData` (station), `DeviceItemData` (rack, modules, submodules, interfaces, ports, IO controllers), `NodeData` (address node of an interface), `SubnetData`, `S7ControllerTargetData`/`NonProgrammableTargetData`, `AddressManagerV2Data`/`AddressManagerNGData`, `HmiConnectionPointData`, `DomainData`, `OpcUaServerConfigurationData`, `WebApplicationData`.
- These objects are read with the existing reader **without decoding problems**. The parameters are stored as named expando attributes (`IPersistentExpandoData`), e.g. `NodeIPAddress` 3232235521 = 192.168.0.1, `NodeIPSubnetMask`, `PnNameOfStation`, `PositionNumber`, `OrderNumber`, `FwVersion`, `ConfigObjectTypeName` (catalog entry, e.g. `S71500\RACK\MDD_…`).
- **Apparently only what deviates from the catalog is stored:** the CPU in 039_fw41 carries only 7 expando attributes (`ProtectionLevel`, `EnablePutGetConnections`, encrypted passwords …), no cycle time, no clock memory, no startup behavior. The default values presumably come from the hardware catalog of the installation (H-HW-01).
- Not yet decoded: blobs `IConfigBaseData.AdditionalInfos` and `PersistentExpandoAttributeFlags` (on every HW object), `AddressMap` (AddressManager) and `IAddressAttributes.AM_x_AddrData_y` (I/O addresses), `DnsAddressContainer`, `RetainMemorySizePerRange`/`MemorySizePerRange`.
- Parser today: device, device group, CPU article number and firmware. Nothing else from Z1.1.
- Truth available: `002_cpu_truth\hardware.aml` (CAx export) and `device_PLC_1_details.json` (device tree via TiaMcpXE).

## Fundamental question for the user (decides the criterion "all properties")

If H-HW-01 is confirmed, default values are not stored in the project file. Then there are two options:
1. The parser emits only what is in the file (deviating values plus catalog reference) and marks everything else as "default per catalog".
2. Additionally, a default value table per catalog entry is generated from our own TIA installation via Openness (own data, no third-party code) and shipped, so that the parser can emit every parameter with a value.

**User decision 2026-10-24 (after H2):** option 1. For now only what is in the file is considered. Default value tables and mixed forms may come later.

## Constraint: Openness scope (GOALS.md section 4, user 2026-10-25)

Only what the Openness interface can read or write is analyzed (attributes, services, export/import; exception: project library). Consequences for this plan:
- Previous findings and samples remain unchanged, even where they go beyond that (hidden submodules such as `CpuCommon`, `CPUexecUnit`, `OPC UA_1`, H-HW-03, cable expandos of the ports, `PnIoSendClockFactor`); the parser keeps emitting them.
- New steps only for settings that Openness can read or write. The criterion is the Openness side (attribute via GetAttribute/SetAttribute, service such as `PlcAccessLevelProvider`, certificate or UMAC API, export/import); checked with the Openness help (help ZIP `TIAPortalOpennessenUS`) and `help` of TiaMcpXE.
- Sync role, IRT and isochronous mode remain dropped (H5).

## H0: TiaMcpXE capabilities for hardware (as of 2026-10-24, from `help` and a probe on 002)

- **DeviceItem attributes:** `TiaDeviceItem(getDetails)` returns all Openness attributes (GetAttributeInfos/GetAttribute: name, value, writable) of a DeviceItem, `setDetails` writes them (`attributesJson`, type per GetAttributeInfos) and scalar CLR properties (`propertiesJson`). Conditional attributes only appear after being enabled (e.g. `ClockMemoryByteAddress` after `ClockMemoryByte`, 11 `Webserver*` after `WebserverActivate`). Openness shows only the visible items (H-HW-03); the parameters of invisible submodules appear on the CPU item.
- **Services:** `serviceList`/`serviceGet`/`serviceSet` for Openness services, among others `PlcAccessLevelProvider` (access level), `WebserverUserManagement`, `WebserverUserDefinedPages`, `SystemWebPagesFeature`, `LocalCertificateManager`, `PlcMasterSecretConfigurator`, `SysLogConfigurationManager`, `OpcUaUserManagement` (partly `available:false` on the CPU 1513 V2.9).
- **Modules:** `plugLocationsList`, `plugNew` (from catalog, `typeIdentifier`), `plugMove`, `plugCopy`, `delete`, `changeType` (type/firmware), `moduleTypeSearch`; catalog search `TiaDevice(typeSearch/catalogSearch)`. GSD parameters `gsdPrmDataGet/Set`.
- **I/O addresses:** `addressList`, `addressSpaceList`, `addressSetStart`, `addressAssignRange`, `processImageAssign` (process image partition to OB), `channelList`, `channelTagsGet`, `hwIdentifierList` → H3 feasible.
- **Networks:** `TiaNetworkSubnet` (create/rename/delete subnet, connect nodes, MRP and sync domains with participants and attributes), `TiaNetworkNode` (node attributes IP/mask/router/PROFINET name/number, `listAttributeInfos`, **port interconnection `portConnect`/`portDisconnect`**, MRP instances, I-device transfer areas, IM port), `TiaNetworkIoSystem` (create IO system, connect IO device), `TiaNetwork` (find interfaces/ports, `connectionCreate/Set/Delete` for S7, TCP, UDP, ISOonTCP, ISO, FDL, PtP connections, `hmiConnectionIntegrate`) → H4 and H5 feasible.
- **CAx:** `TiaCax(export)` AML of the project or of a station (stations, modules including GSD, subnets, IO systems, addresses, channels, tags, topology), `inspect` offline, `import`.
- **Other:** `featureExport` (GSDML of an I-device, OPC UA nodeset, PSC …), `webPagesGenerate`, `compile` per item, online/download (not for samples).
- **Gaps:** H5 sync role, IRT and isochronous mode cannot be set (IoController/IoConnector attributes, MCP-086). A server restart during work loses binding and lease → TiaMcpXE backlog MCP-083. A GSDML installation (H6) does not exist as an operation and remains subject to the user's approval.
