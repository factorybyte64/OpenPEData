## Finding

- **The type is FP_Interface, not FP_Basic:** the only new thing is the version **FP_Interface 0.0.7** (default, released 2026-10-23 21:58 UTC), a complete copy of 0.0.6 (its own hidden device, 103 objects). FP_Basic is unchanged (0.0.1).
- **Storage of the local tag:** `HmiTagData` "LocalInt" in the hidden device of the version, in the table **"Default tag table"** (`TagTable` → Default tag table, `Content` there), with `DataTypeRef`/`HmiDataType` Int, acquisition cycle T1s, scope System.
- **Difference to the interface tag:** interface tags are in the separate, GUID-named interface table (`ILFaceplateToTagTable`) and each has an entry in `IFaceplateInterface.TagInterfaceProperties` (F05.md). The local tag has **no** interface entry and no link from the content; it is only reachable via the Default tag table. This table exists in every hidden device (fixed core, HIDDEN-DEVICE.md, otherwise only the 9 system tags there).
- **Limits:** **not set** in the saved state: `IHmiTagStructureAttributes.LimitLowType`, `LimitLowHighType`, `LimitHighLowType`, `LimitHighType` = NoLimit, the associated `Limit…Constant` empty (ScalingHmiLow/High 0/100 and ScalingPlcLow/High 0/10 are the default values of the linear scaling, `LinearScaling` False). So the limits of an HMI tag are stored as attributes on the tag (type + constant), not in expandos; not yet confirmed with set values.
- **Binding:** no screen item references LocalInt (only incoming link: `Content` of the table). I_IOField1 still has the static text ProcessValue "HmiTag_Ext1" (F01, MCP-025), no dynamization.
- **Core:** without special handling, LocalInt counted towards the fixed core (80). Local tags now count as content-dependent; the core stays 79.

Openness provides no truth for tags in the hidden device of a type (only instances, type metadata), hence fixed expectations from the diff.
