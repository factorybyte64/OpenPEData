## Data type codes (`InterfaceProperties[].DataType`)

| Data type (editor) | Code | Default in the type (file) | Openness value of the helper instance |
| --- | --- | --- | --- |
| Bool | 1 | False | False |
| LInt (64-bit integer) | 5 | 0 | 0 |
| ULInt (Unsigned 64-bit integer) | 9 | 0 | 0 |
| LReal (Floating point number) | 11 | 0.0 | 0 |
| WString (Configuration string) | 14 | "" | – |
| Color | 1282 (0x502) | 0xFF0000FF | 0xFF0000FF |
| Graphic | 65542 (0x10006) | – | – |
| Multilingual text | 65544 (0x10008) | – | empty ProjectText |
| Authorization | 65555 (0x10013) | – | – |
| Parameter set type | 65575 (0x10027) | – | – |
| Resource list | 65585 (0x10031) | – | – |

The codes form a common enumeration with the data types of the interface tags (there confirmed 1 Bool, 3 Int, 14 WString, 30 Struct, F05/F40). Values below 0x10000 are simple data types, 0x502 the color, 0x100xx reference types (graphic, text, authorization, parameter set, text list). A default is only stored where the type has a value (Bool, numbers, WString, color); reference types have none. According to the user (2026-10-23), the property interface editor does **not allow setting default values**; so the stored `Default` is the fixed system default per data type (also F40 TempControl.TankColor 0xFF0000FF). Custom values are only set on the instance; their encoding is shown by F40 (color, WString, text list, multilingual text); numbers ≠ 0, graphic and authorization on an instance are still pending.

## Several versions of one type (list item 12)

| Version | Object | Content | Hidden device | Objects | VersionGuid | Properties |
| --- | --- | --- | --- | --- | --- | --- |
| 0.0.1 | 0003:00d3:248a | 1004:00cd:24de | 100e:0010:248b | 89 | 526b9f5a… (as F05) | none |
| 0.0.2 | 0003:00d3:2c50 | 1004:00cd:2c88 | 100e:0010:2c6b | 89 | 32d2de6c… | 11, P_ULInt as LInt (5) |
| 0.0.3 default | 0003:00d3:2caa | 1004:00cd:2ce2 | 100e:0010:2cc5 | 89 | 38db54e9… | 11, P_ULInt as ULInt (9) |

**Every new version is a complete copy** with its own content (ILFaceplateTypeData), its own hidden device and its own VersionGuid; the link structure is the same for all, only the default version has `DefaultVersionToType`. This answers the open question from RELEASE.md: "Edit type" creates a new version as a copy, and the release then changes this copy in place. The properties themselves do not create objects (89 objects with and without properties), they are only stored in the map on the content. The property GUIDs stay the same across versions.
